# 3. Tools and Technical Concepts

## Virtualisation

A hypervisor allows multiple guest operating systems to run on one physical computer. Virtual machines make it possible to create repeatable test environments, take snapshots, and separate lab activity from the host. Isolation depends on correct network and hypervisor configuration; virtualisation alone is not a security guarantee.

## Kali Linux

Kali Linux is a Debian-based distribution maintained for penetration testing and security auditing. In this lab it serves as a controlled test workstation. Its presence does not mean every tool available in Kali was used.

## Windows endpoint

The Windows VM represents the monitored endpoint. Windows produces operating-system event records through its event logging infrastructure. Which records appear depends on audit policy, enabled providers, system configuration, and the activity performed.

## Sysmon

System Monitor (Sysmon), part of Microsoft Sysinternals, is a Windows system service and device driver that logs detailed system activity to the Windows Event Log. Depending on its configuration, events can include process creation, network connections, image loading, file creation, registry changes, and other activity.

Sysmon is a telemetry source, not a SIEM and not a complete endpoint protection product. Its event coverage depends on the installed version and configuration. A missing event does not automatically prove that an action did not occur.

## Splunk

Splunk is a platform used to ingest, index, search, and visualise machine-generated data. In a security-monitoring workflow, analysts can search endpoint events, filter by time and host, compare fields, and build dashboards or alerts.

Splunk only analyses data that is successfully collected and ingested. Search results depend on input configuration, parsing, timestamps, indexes, permissions, and retention.

## SIEM

A Security Information and Event Management system centralises security-relevant data and supports search, correlation, alerting, and investigation. A SIEM does not automatically identify every malicious action. Detection quality depends on telemetry coverage, parsing, detection logic, tuning, and analyst interpretation.

## Telemetry, logs, and alerts

- **Telemetry:** Observable data generated by systems or applications.
- **Log/event:** A recorded observation with fields such as timestamp, provider, host, event ID, and event details.
- **Alert:** A notification produced when configured detection logic or a rule's conditions are met.
- **Incident:** A security event or group of events that warrants investigation and response. Not every alert is an incident.

## TCP and reverse connections

TCP is a connection-oriented transport protocol. A TCP connection is commonly established using a three-way handshake: SYN, SYN-ACK, ACK. A reverse connection is initiated from the target-side process back toward a listening system. In an authorised lab, observing such traffic can help an analyst understand process and network telemetry. A connection alone does not establish malicious intent; context and authorisation matter.

## Indicators of Compromise (IOCs)

An IOC is an observable artefact that may indicate compromise, such as a file hash, suspicious domain, IP address, process path, or registry value. IOCs require context: an IP address or filename alone is rarely conclusive.

## False positives and false negatives

- **False positive:** A detection flags benign activity.
- **False negative:** Relevant malicious activity is not detected.
- **Detection gap:** Required telemetry or logic is missing, misconfigured, delayed, or unavailable.

A lab test can demonstrate a specific detection path; it cannot establish universal detection effectiveness.
